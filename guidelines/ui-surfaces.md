# UIは共同作業か個人操作かで表示先を選ぶ

状態：表示先の方針は決定済み。共通化の改善案は末尾に記載する。
確認日：2026-10-24。

## ワールドで一緒に使う道具は3Dに置く

共有のインスペクタ、新規作成、今後のマテリアル編集などは、ワールドに置く3Dパネルとして扱う。
参加者が同じ対象や選択内容を見て作業でき、パネルそのものを持って配置できる形にする。

個人のセッションメニュー、ダッシュ、設定、ホーム／ライブラリは2Dオーバーレイに置く。
ファイル選択などOSの操作が必要なものは、ローカルのダイアログを使う。

| UI | 表示先 | 共有する結果 |
|---|---|---|
| 共有インスペクタ | 3Dパネル | パネル配置、対象、編集したオブジェクト値 |
| Resources | 3Dパネル | パネル配置、対象 Slot、付けた ScriptComponent |
| Script Editor | 3Dパネル | パネル配置、対象・script_id、共同編集ドラフト経由の Apply |
| 新規作成 | 3Dパネル | パネル配置、選んだ形状、作成した物体 |
| セッション一覧・参加操作 | 個人のオーバーレイ | 必要な参加要求だけをサービスへ送る |
| Projects（ローカル） | 個人のオーバーレイ | 端末内の Project メタ／快照。共有パネルは自動生成しない |
| 参加者一覧・セッションチャット | 個人のオーバーレイ | Rustが確定した参加者と一時的なチャット履歴を表示する |
| ダッシュ・ユーザー設定 | 個人のオーバーレイ | 表示名やアバターなど、共有対象の設定値のみ |
| 個人ライブラリ | 個人のオーバーレイ | 選択後にワールドへ配置した物体 |
| ファイル選択 | ローカルのOSダイアログ | 取り込んだアセットと配置した物体 |
| 外部インスペクタ | ローカルのOSウィンドウ | フィールド編集。Script 編集は Script Editor へ |

共有インスペクタのピンは、同じパネルを自分の画面では2D、ほかの人からはその人の視点面へ張り付いた3Dとして見せる。2Dも3Dも同じHTMLインスペクタを使う。窓の中の位置は共有する。板の画素は各クライアントがオフスクリーンのHTMLを描いて貼る。板は右クリックで保持できるが、物体一覧・階層・選択対象には出さない。`↗`で開く別ウィンドウは個人の表示のままで、共有パネルを作らず、位置や大きさも伝播しない。
Script の作成は共有 Resources パネルから（選択 Slot へ一体の ScriptComponent を Attach）。編集は共有 Script Editor。インスペクタはオブジェクト欄のみで、Script Editor へのリンクを出す。空の Lua と Node graph から作り始める。カウントダウンカメラのように複数の Component と Script を組み合わせた完成品は、ワークショップ作品として保存・配置する。基本の Camera は新規作成に残す。Projects の v0 はローカル FS のみ（[Projects](../docs/projects.md)）。
2D窓の位置・大きさ・タブ・スクロールを、3Dパネルへ伝播させない。
Play/Editは各クライアントの道具の表示状態とする。Playでは新しいインスペクタや制作リングの入口を隠し、Editではドックから共有インスペクタをピン留めできる。モード切り替えで共有3Dパネルを削除せず、Rustの編集権限や共有ワールドの状態も変更しない。

## 共有する内容と端末内の表示状態を分ける

Rustには共有データ、検証、確定処理、保存を置く。
Godotには受信した表示用コピー、マウスやキーボードの状態、UI部品、テクスチャを置く。
Goアダプターは配送を担当し、UIやワールドの編集規則を解釈しない。

| 状態 | 扱い |
|---|---|
| 3Dパネルの位置・回転・スケール、表示対象、共有タブ | 共有・保存 |
| インスペクタの確定値、スクリプト、作成した物体 | 共有・保存 |
| 編集中のドラフト・選択範囲・編集中の人 | 共同編集に必要な範囲で一時共有。ワールドの永続データとは分ける |
| ホバー、押下対象、キーボードフォーカス、OSカーソル | ローカル |
| GPUテクスチャ、キャッシュ、描画品質 | ローカル |

共有パネルでも、各人の入力フォーカスは独立させる。
他の人が入力欄を選んだことを理由に、自分のマウスやキーボードを奪わない。
一方、同じ共有フィールドへの編集競合はRust側の編集リースで処理する。

## 表示先を増やしても操作の意味を増やさない

表示言語はクライアントごとの個人設定とし、共有パネルも各人の言語で描画する。
言語を切り替えるために共有データを書き換えたり、入力中のフォームやグラフを作り直したりしない。
ユーザーが書いた名前・チャット・コード・WorldTextは自動翻訳から除外する。
動的な文は翻訳する書式と値を分け、古い状態表示の翻訳が新しい表示を上書きしないようにする。
実装と確認方法は [表示言語](../docs/localization.md) を参照する。

同じ「名前を変更する」操作は、3Dパネルからでも2D窓からでも同じ編集要求を送る。
通信は既存の要求・応答Brokerを通し、フィールドの型や変更可否はComponentの登録表で判断する。

ノードグラフの型は接続口の色だけに任せず、型名も併記する。`ANY`は未確定の値として表示し、Field参照や既存の接続から型が分かる場合は表示だけを具体化する。型の確定と実行時の検証はRust側に置く。

共同編集するノードグラフの下書きは、JSON文字列全体を書き換えずにノード・接続単位の操作としてホストへ送る。ホストは操作を検証して順序を決め、セッション参加者へ下書きを配る。これにより別のノードへの同時編集を残す。下書きは永続化せず、`Apply graph` でホストの最新の下書きからScriptComponentの更新コマンドを作り、通常の検証と保存を通す。実装は [graph_documents.rs](../crates/core/src/graph_documents.rs)、[shared_script_view.gd](../client-godot/shared_script_view.gd) を参照する。

現在の外部インスペクタは、3Dのテクスチャを拡大表示する方式ではない。
共通の編集処理を使い、デスクトップ用のレイアウトで同じデータを表示する。
実装は [desktop_inspector.gd](../client-godot/desktop_inspector.gd) を参照。

## 改善案：パネル本体・内容・入力・描画の境界を明確にする

次の分離を進める。以下は目標であり、すべて共通化済みという意味ではない。

| 担当 | 持つもの |
|---|---|
| パネル本体 | 共有する配置、寸法、保持、寿命 |
| 内容 | インスペクタや新規作成の表示モデルと操作コマンド |
| 入力 | 各端末のポインター、押下、ドラッグ、文字入力先 |
| 描画 | GodotのUI部品、表示面、描画解像度 |

現在はWorldPanelを共有しているが、内容の生成には種類ごとの分岐がある。
編集セッションの開始処理にも`inspector_target`を前提とする箇所が残る。
次の共有UIを追加するときは、この前提を確認し、同じ処理のコピーを増やす前に共通化を検討する。

関連コード：[world_panels.gd](../client-godot/world_panels.gd)、[replication.rs](../crates/core/src/replication.rs)。
