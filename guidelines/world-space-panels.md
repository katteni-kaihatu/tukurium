# 3Dパネルは表示と操作が一致するように作る

対象：Godotのワールドパネルと、対応するRustのComponentを変更する開発者。
確認日：2026-10-24。操作規則は決定済み。末尾の課題は未実装の改善案。

新しいパネルを作る前に [UIの表示先と責務](ui-surfaces.md) を確認する。
以下の入力規則と共有状態の扱いを読み、変更箇所に応じて表示・検証の節を参照する。

## 既存のWorldPanelに内容を載せる

共有パネルは、Rust側のSlotにWorldPanelと内容のComponentを持たせる。
現在はInspectorViewとCreationViewがあり、共通の表示面で描画する。
パネルの種類ごとに独立したMesh、Collider、入力転送を作らない。

Godotでは、作成パネルはSubViewportのUIをテクスチャとして表示面へ貼る。
共有インスペクタは、HTMLホストが使えるとき同じHTMLページをオフスクリーンで描き、撮った画素を板へ貼る。ホストが無い・ヘッドレス・`--script`では、これまでどおりSubViewportの`inspector_view`を使う。
入力は自動では届かないため、ワールド上の交点をUIの座標へ変換して転送する。HTML板では交点をホストへ送り、ページ側でポインターを再現する。
SubViewportの役割は [Godot公式ドキュメント](https://docs.godotengine.org/en/stable/classes/class_subviewport.html) を参照。

実装の入口は [world_panel.gd](../client-godot/world_panel.gd)、生成・入力の管理は [world_panels.gd](../client-godot/world_panels.gd)。
Rust側は [panels.rs](../crates/core/src/panels.rs) と [Component登録表](../crates/core/src/replication.rs) を参照する。

## FPSの視点操作をパネルに奪わせない

| 入力 | 動作 |
|---|---|
| FPS操作中の左クリック | 視点中央でUIを操作。マウスの捕捉を維持する |
| FPS操作中のドラッグ | UIへ移動を送りながら、視点も動かす |
| TPS・Fly camera・カーソル解放中の左クリック | マウス位置でUIを操作する |
| FPS中の右クリック | Colliderを持つ対象を保持。見出しの上でも同じ |
| カーソル解放中、Script Graphの空白で右クリック | グラフ内のノード追加メニューを開く。パネルの他の場所とFPS中の保持操作には影響させない |
| Ctrl＋右クリック | 参照を取り出す、または手放す |
| Ctrl＋Shift＋右クリック | 参照元の共有値をコピーする |
| Esc | 保持やUIの入力状態を解除し、カーソルを表示。共有パネルは残す |

パネルを開いただけで移動を止めない。文字・数値・コードの入力中は、移動・ジャンプのキーを入力欄へ渡す。
マウスの捕捉とキーボードフォーカスは別の状態として管理する。
起動時のFPS視点はマウスを捕まえず、ワールドへのクリックで操作を始める。

## ホバー・押下対象・文字入力先を区別する

ホバーは現在指している場所。押下対象は、ボタンを押し始めた場所。
ドラッグ中に指先がパネル外へ出ても、ボタンを離すイベントは押下対象へ届ける。
保持中の右ボタンの解除を、UIの参照操作へ渡さない。

キーボード入力先は、クリックした入力欄で決める。
カメラだけが動いても交点は変わるので、押下前に交点でホバーを更新する。
別の欄や余白を押した場合は、以前の入力欄からフォーカスを外す。
同じ入力欄への再クリックでは、不要に編集リースを取り直さない。

Esc、ウィンドウのフォーカス喪失、パネル削除、切断でも、押下・ドラッグ・文字入力の状態を解除する。
将来VRの左右の手を扱う場合は、これらをポインターごとに持つ。現在の単一ポインター実装をそのまま二重入力に使わない。

## 見えている面とクリックできる面を揃える

入力座標は、レーザーの交点からパネルのローカル座標へ戻し、UIの論理座標へ変換する。
回転・非等方スケール・画面のリサイズ・スクロールでも同じ経路を使う。
描画面、Collider、座標変換が別々の寸法を参照すると、見えるボタンと当たる位置がずれる。

裏面を表示するか、裏面から操作できるかを一緒に決める。
手前の物体に隠れたボタンへ入力を通すかどうかも、見た目と一致させる。
パネルを読みやすくする目的で深度判定を無効にする場合は、入力側にも同じ判断が必要になる。

文字や細い線は、実際の閲覧距離で確認する。パネルの物理サイズ、UIの論理サイズ、描画解像度を区別し、画質の変更で操作位置が変わらない設計を目指す。
ドロップダウン、色選択、ツールチップ、IME候補も確認する。パネル端で切れるものを、通常のボタンのテストだけで完了扱いにしない。

## 共有する値とパネルの寿命を定義する

表示対象、共有タブ、スクロール、選択した形状など、共同作業に必要な値は内容のComponentへ置く。
ホバー、OSカーソル、GPUリソースは端末内に置く。編集ドラフトや占有は一時共有し、永続データと分ける。

共有パネルの削除は全員へ反映される。誰が削除できるか、未確定の編集をどう終えるかを実装時に決める。
新規作成パネルは、作成に成功したら閉じる。失敗時は残してエラーを表示する。
再接続や連打で、同じ作成要求が二重に実行されないことも確認する。

## 変更箇所に応じて入力経路を検証する

Godotの部品を直接呼ぶテストだけでは、座標変換や入力の取り合いを検出できない。
実際のレーザー判定、SubViewportへの転送、Rustへの要求まで通す。

| 確認する動作 | 主なテスト |
|---|---|
| FPSで欄・タブを選ぶ、文字入力、余白で編集終了、右クリック保持 | [panels-integration.mjs](../tests/panels-integration.mjs) |
| 新規作成、移動・ジャンプ、保持・回転・拡縮、作成後の自動終了 | [creation-integration.mjs](../tests/creation-integration.mjs) |
| 参照の取り出し、別ウィンドウへの受け渡し | [reference-integration.mjs](../tests/reference-integration.mjs) |
| 起動時のカーソル、Esc、視点切替、オーバーレイ | [hud-integration.mjs](../tests/hud-integration.mjs) |

例えばパネル入力を変えた場合は、リポジトリ直下で以下を実行する。
テストが参照するrelease版Engine、アダプター、中継の実行ファイルを先に用意する。パスは各テストのソースに記載されている。

```powershell
node tests/panels-integration.mjs --rendered
node tests/creation-integration.mjs --rendered
node tests/reference-integration.mjs --rendered
```

新しい共有データを追加した場合は、ホスト・ゲスト・途中参加・保存復元も確認する。
回帰テストでは、以前の実装で失敗する再現条件を残す。

## 未実装の課題を現行動作と混同しない

2026-10-24時点で、次は改善案として残っている。

| 課題 | 現状と進めたい方向 |
|---|---|
| 寸法と画質の分離 | 高さを1.6として、共有する解像度の比から横幅を計算している。物理寸法・論理サイズ・端末の描画解像度を分離する |
| 裏面の扱い | 両面を描く一方、入力は表側に限定している。表示と入力の方針を揃える |
| 出現位置 | カメラ前方の固定距離に出す。壁や物体との重なりを避ける配置を検討する |
| 内容の拡張 | 内容の生成に種類ごとの分岐、編集セッションにインスペクタ前提が残る。新しい共有UIの追加時に整理する |
| 作成と終了の一体化 | 現在は作成成功後に別要求でパネルを削除する。同時操作での一貫性を強めるならRust側の一操作にまとめる |
| 多数のパネル | 描画更新にはUPDATE_WHEN_VISIBLEを使う。距離別の解像度や全パネルの描画予算は未整備 |

参考：[Resonite WikiのCanvas](https://wiki.resonite.com/Canvas) はサイズ、Collider、レーザー通過、裏面描画などを扱う。
これは設計を比較する資料であり、tukuriumに同じ機能が実装済みという意味ではない。
