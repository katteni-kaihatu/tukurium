# インスペクタの操作

- 初期視点はFPS。起動時はマウスを捕まえず、ワールドをクリックするとFPS操作を開始する。`F5`でFPS・Fly camera・Third personを切り替える。
- 左上で`Play`と`Edit`を切り替える。起動時はPlay。Playではインスペクタの新規表示や制作リングを使わず、参加者・チャットなど遊ぶためのUIを表示する。Editにするとドックへ「インスペクタ」が加わり、選択中の物体を個人用2Dウィンドウで開ける。Playへ戻すと個人用インスペクタを閉じるが、既存の共有3Dパネルは削除しない。モードは各クライアントの表示状態で、ワールドの権限ではない。
- Edit中はミドルクリックでリングメニューを開く。`Inspector 2D` と `Inspector 3D` を選べる。もう一度ミドルクリック、右クリック、または `Esc` で閉じる。右クリックで物体を保持中、または視点操作中のミドルクリックは無視し、保持を続ける。
- `Esc` で青いゲーム内カーソルを表示すると、画面下のドックがスライドして現れる。独立したアイコンからセッション・インベントリ（マイライブラリ）・ワークショップ・設定を開く。Edit中はインスペクタも加わる。セッションはHNと参加先、インベントリは保存作品、ワークショップは公開作品をそれぞれ専用ウィンドウに表示し、左側の切り替えタブはない。個人ウィンドウを開いていないときは、もう一度 `Esc` でドックをしまえる。
- 左に参加者一覧、右にセッション全体のチャットを表示する。参加者は自分を先頭に置き、ほかの人を距離順に「すぐそば（3m以内）」「近く（15m以内）」「とおく」へ分ける。チャットは入力してEnterまたは「送信」で投稿する。ワールド保存には含まれず、ホストのセッションが続く間は途中参加者も直近200件を読める。
- FPSなどマウスを捕捉して3D操作中は左右のパネル全体が薄くなり、パネルへの入力を受け付けない。`Tab`で左右を一時的にしまい、もう一度押すと戻す。画面端の矢印でも戻せる。チャット入力中や個人ウィンドウを開いているとき、`Tab`はパネルの切り替えに使わない。
- リングメニューの `新規作成…` は、共有の3D作成パネルを開く。Box・Sphere・Capsule・Cylinder・Cone・Torus・Grid・Quadをプレビューから選んで作成する。ダブルクリックでも作成できる。`空のSlotを作成` と `テキストを作成` では、描画部品のないSlotと、WorldText付きのSlotをそれぞれ新規作成する。FPSからTPSへは切り替えない。
- 作成パネルはインスペクタと同じWorldPanelを使い、位置・回転・スケール・選択した形状を共有・保存する。右クリックで保持し、移動・回転・拡縮できる。パネルを開いたまま移動・ジャンプでき、パネル内のクリックだけをUI操作として扱う。`×`で共有パネルを削除する。
- 1つ作成に成功したら、作成パネルは参加者全員の画面から閉じる。作成した物体はワールドに残る。失敗した場合はパネルを残してエラーを表示する。
- 作成した物体の形状はRust側に保存・同期し、Godotがメッシュを生成するためファイル転送はない。現在の当たり判定は外形を覆うボックスで近似する。

## カメラアイテムで撮影する

Editの「新規作成…」パネルで「Camera を作成」を押すと、カメラの形状と`Camera`コンポーネントが付いた共有Slotが置かれる。カメラの位置・向きと`Enabled`はRustが保存・同期する。右クリックで保持したりインスペクタで編集したりできる。`Enabled`がオンなら、Play/Editどちらでも、カメラを選択して下の「カメラ」を押すか、カメラ本体をダブルクリックすると撮影ウィンドウが開く。既存Slotにもインスペクタから`Camera`を追加できる。

撮影ウィンドウでは、`WASD`で前後左右、`Q/E`で上下へドローンを動かす。右ドラッグで向きを変え、`Shift`で加速、プレビュー上のホイールで画角を変える。移動中の位置・向きはほかの参加者にも一時表示し、「配置して閉じる」または`Esc`でRustへ確定して保存する。「移動を戻す」は未確定の操作を取り消す。ウィンドウ内の操作中はプレイヤーの移動入力を止める。

「撮影」はワールドと参加者のアバターを写し、自分のアバターも入る。ウィンドウやチャットは写真に入れない。撮影後は「ローカル保存」で自分の`user://photos`フォルダーへPNGを書き出すか、「写真をワールドに置く」で画像アイテムを参加者全員に共有できる。実際のローカル保存先はウィンドウの下部に表示する。ワールドの写真アイテムは既存のライブラリ保存操作でも作品として扱える。共有用写真は画像の上限に合わせてJPEGへ縮小するため、ローカルPNGと画質が異なる。

CameraのSlotにScriptを付けると、クリックを起点にタイマーを組んで撮影できる。タイマーは共有Scriptの状態と`ctx.time`で管理し、`ctx:capture_camera(ctx.self)`は撮影だけを要求する。Cameraコンポーネントがオンの自身のSlotだけを撮影できる。新しく作るCameraには空の`WorldText`が付く。既存のCameraにはインスペクタの`+ Add Component`から`WorldText`を追加できる。

完成済みのカウントダウンカメラは、ワークショップで「カウントダウンカメラ | ノード」を探し、ライブラリに保存してから配置する。Camera・WorldText・ノードグラフとフィールド参照が結び付いた作品で、Cameraをクリックすると共有のテキストが`3 → 2 → 1`と変わり、消えてから操作した本人が撮影される。秒数はScript Systemsの`p_duration`で変更できる。自分で組み立てる場合は、通常のCameraにScript Systemsの`+ Node graph`または`+ Blank script`でロジックを追加する。

```lua
return {
    name = "Shutter",
    fields = { label = { type = "field_ref" } },
    on_interact = function(ctx)
        ctx:set_state("deadline", ctx.time + 3)
    end,
    update = function(ctx)
        local deadline = ctx:get_state("deadline", 0)
        if deadline <= 0 then return end
        local remaining = math.max(0, math.ceil(deadline - ctx.time))
        if remaining ~= ctx:get_state("shown", -1) then
            ctx:write_field(ctx.self.Shutter.label, remaining > 0 and tostring(remaining) or "")
            ctx:set_state("shown", remaining)
        end
        if remaining == 0 then
            ctx:capture_camera(ctx.self)
            ctx:set_state("deadline", 0)
        end
    end
}
```

ワークショップ作品のノードグラフでは、`On Interact`が`Time + Countdown seconds`を`deadline`へ保存する。`On Update`が`Ceil(deadline − Time)`を計算し、`To String → Write Field`でWorldTextへ書き込む。期限に達すると空文字を書いてから`Capture Camera`を通す。グラフ内の`Display`は編集画面の値確認用で、ワールドに文字を表示するのは`Write Field`と`WorldText`の組み合わせ。撮った写真は本人の`user://photos`へPNGで自動保存される。共有したい場合は「写真をワールドに置く」を押す。撮影要求は一時的な操作で、カウントダウンの文字と期限は共有・保存される。

- カーソルが表示された状態で `Esc` を押すと、リング、設定、手前の個人ウィンドウを一つ閉じる。カーソルは表示したままにする。複数の個人ウィンドウを同時に開け、ドックの同じアイコンをもう一度押すとそのウィンドウだけを閉じる。共有の3Dパネルはワールドに残る。FPS操作に戻るにはワールドをクリックする。
- FPS操作中は視点中央で3Dパネルのボタンを押す。クリックやドラッグ中もマウスは視点操作のままで、カーソルには切り替わらない。TPS・Fly cameraやEscでカーソルを出した状態では、マウスポインターでパネルを操作する。
- 上部バーは個人画面を開いても常時表示し、Play/Edit、FPS、同期状態、ローカルEngineとの往復時間を示す。「ユーザー」「セッション」の入口は下のドックにまとめる。個人画面の見出しをドラッグして移動し、右下をドラッグしてサイズを変えられる。位置とサイズはそのクライアントだけの表示状態。左のWORLD・PEOPLE欄と常設の操作説明は表示しない。
- Edit中の`Ctrl+I`：選択中の物体の共有インスペクタをワールド内に作る。
- Edit中の`Ctrl+Shift+I`：ローカルの2Dインスペクタだけを開く。ワールドにSlotや3Dパネルを作らない。
- パネル右上の`↗`：表示中の物体を、独立した2Dインスペクタで開く。Windows標準の閉じるボタンはそのウィンドウだけを閉じる。3Dパネルの削除も2D窓を閉じない。最小化・最大化・サイズ変更はWindowsの操作を使う。
- パネル内の`×`：共有パネル自体を削除する。他の参加者の表示からも消える。
- Edit中の`I`：ローカルの2Dインスペクタを開く。

## 鏡と遠距離レーザー

Editの「新規作成…」パネルで「Mirror を作成」を押すと、2m角の平面メッシュと`Mirror`コンポーネントが付いた共有Slotを置ける。位置・回転・スケールと`Enabled`はRustが同期・保存する。既存のQuadにもインスペクタから`Mirror`を追加できる。`Enabled`がオンなら、各クライアントは自分の視点から反射画像を描き、自分のアバターも映る。カメラの撮影ウィンドウを使っている間は、そのドローン視点に合わせて反射する。鏡は両面から映り、反射面同士の再帰描画はしない。見えている鏡の反射は、鏡と視点が静止していてもGodotの描画フレームごとに更新する。鏡の枚数に応じて描画負荷は増える。

FPSの操作レーザーと右クリック保持は、従来の6m制限をなくした。空間自体の有効座標が各軸±1000mなので、判定距離は全域を覆う4000mとする。共有3Dパネルのポインターとリングの対象選択にも同じ距離を使う。保持中のホイールによる距離調整もこの範囲まで行える。

別ウィンドウは専用の2Dレイアウトで描画する。Windows標準の枠をドラッグして移動・リサイズし、階層と詳細の境界をドラッグして幅を調整できる。位置・大きさ・分割幅・スクロールは自分のPCだけの表示状態で、3Dパネルや共有データへ反映しない。文字やボタンの大きさを保ち、ウィンドウに合わせて表示範囲が広がる。

右側の `Object` / `Scripts` タブでフィールドとLuaエディタを切り替える。左の階層は両方のタブで表示する。2D窓のタブとスクリプトの選択はローカルな状態で、3Dパネルの表示は切り替えない。3Dパネルにも同じタブがあり、こちらの選択はその共有パネルを見ている参加者全員に同期する。入力中にタブを変えた場合は、送信中の編集が落ち着いてから切り替える。フィールドやコードの編集内容は従来どおり共有する。

既存Slotの部品は `Object` タブの `+ Add Component` から探して追加する。候補はRustの登録表から受け取り、MeshRenderer・WorldText・Mirror・Camera・ValueNumber・ValueBool・ValueText・Button・ContactSensor・PlanarMotionを追加できる。MeshRendererの形状は一覧の上で選ぶ。`Mirror`はQuadかMirrorの平面メッシュがあるSlotだけに追加できる。`PlanarMotion`は親を持たないSlotで、RendererとSolidなColliderがある場合に追加できる。付いたコンポーネントは各欄の`Remove`で外せる。`Mirror`や`PlanarMotion`付きのSlotでは、それらを先に外してからMeshRendererを外す。機能の`Enabled`は欄内のチェックボックスで切り替える。構造の基礎となるSlotやTransformは一覧に出さない。付け外しは対象SlotのAddressとrevisionを添えた `add_component` / `remove_component` 構造コマンドとしてRustへ送り、登録表で検証する。

Inspector左側の階層でSlotを選び、`Duplicate`の下の`Delete…`から削除する。確認後、対象Slotとその子孫Slotがワールド全体から削除され、共有状態と保存へ反映される。スクリプトやComponentの`Remove`は、その部品だけを外す操作。

`ValueNumber`・`ValueBool`・`ValueText`は、スクリプトやノードから参照する共有値をSlotに置く部品。各Slotに型ごと1つ付けられる。インスペクタで値を編集し、フィールド見出しをScriptの参照欄へ渡す。値は同期・保存され、Write/Driveの対象にもできる。数値は有限値で絶対値10億以下、文字列は80文字以下。

`Button`を付けたCollider付きの物体は、左クリックで`on_button_press`、ボタンを放すと`on_button_release`を実行する。従来の`on_interact`は押したときにも実行される。`Enabled`を切ると押下を受け付けない。`ContactSensor`はColliderが別のColliderと重なり始めたときに`on_contact_start`、離れたときに`on_contact_end`をホストで実行する。相手のSlot IDは`ctx.other.instance_id`またはノードの`Contact Other ID`で読める。接触判定は共有された位置に対して行い、各端末のDriveによる見かけの移動は使わない。

`PlanarMotion`はX/Z平面で物体を動かす簡易部品。`Velocity X/Y/Z`のX/Zに速度を入れるとホストが毎秒20回進め、SolidなColliderと範囲端で反射する。Y速度は使わない。`Drag`は減速率、`Bounce`は反発率、`Bounds`は最小X・最大X・最小Z・最大Z。たとえばホッケーのパックに付け、スクリプトの`Write Field`で`planar_velocity`を設定して打ち出す。位置と速度の確定値は同期・保存される。現段階では矩形Colliderを使う軽量な盤面向けで、得点判定や一般的な剛体物理は含まない。

2D窓の表示対象・階層の表示起点・折り畳みもローカルな表示状態。窓はいくつでも独立して開ける。表示対象が削除されても窓は残り、別の対象を選べる。ワールドのSlot、共有パネルの上限、保存データには含めない。

データの取得、入力の検証、編集要求、フィールド描画は共用し、デスクトップの外枠とレイアウトを `desktop_inspector.gd` で組み立てる。3DのSubViewportの画像を転用しない。入力欄の占有とLua共同編集は2D・3D間でも共有する。2Dの編集要求は共有パネルを参照しない `context: null` を使い、各窓は独自の編集者IDを持つ。ウィンドウで入力中は、プレイヤーの移動・ジャンプを止める。

ワールド内のパネルは共有の描画解像度と同じ縦横比で表示し、標準のクリック判定もその形に合わせる。2D窓のリサイズはこの解像度を変更しない。

フィールドはComponentごとに表示する。紫色の`Local Drive`は、スクリプトがこのクライアントで値を計算している印。入力欄には現在の計算結果、その下に`Shared base`として共有の保存値を表示する。計算結果を直接書き換える入力は無効にし、`Open Rotator →`などのボタンから実際の制御元へ移動する。停止中もDriveが値を保持している間は`paused`と表示する。

フィールド見出しを `Scripts` タブのコード欄へドラッグするか、Ctrl＋右クリックで持ってコード欄をクリックすると、`Read` / `Write` / `Drive` を選べる。選択するとフィールド参照の公開パラメータとLuaの呼び出しを挿入する。`Apply code` で保存する。WriteとDriveを選べるかはフィールドの登録表が示す。`WorldText` の文字列はDriveで時計表示に使える。

ノードグラフの下書きはセッション内で共同編集できる。同じグラフを複数人が開くと、ノードの追加・削除、位置、値、接続、グラフ名の変更がほかの編集者にも届く。異なるノードへの同時変更は両方残り、同じ値や同じ入力ポートへの変更はホストが受け取った順で決まる。下書きはセッション内だけにあり、実行中のScriptとワールド保存には `Apply graph` を押したときに反映する。下書きを破棄して確定済みの内容を開き直す場合は `Reload draft` を使う。

`Write Field`・`Drive Field`・`Read Field` を追加した場合、最初のApplyで `ref_...` の公開パラメータが現れる。対象フィールドの見出しからその欄へ参照を渡すと、参照だけは自動保存される。以後グラフの数字や接続を編集したら再び `Apply graph` を押す。既存の参照を渡し直す必要はない。参照を直すときは欄へ正しいフィールドを渡すか、`Clear` で解除してから渡す。

接続口は色と型名を一緒に表示する。`NUMBER`、`BOOL`、`TEXT`、`VECTOR 3`、`COLOR`、`ROTATION`、`FLOW`を区別し、`ANY`は型が未確定の値を示す。Field参照を設定したRead/Write/Driveや、接続したSelect/Displayは分かる範囲で実際の型を表示する。型が合わない接続は追加せず、その場に理由を表示する。

Driveの制御元はRustが実際に採用したスクリプトIDを渡す。同じフィールドを別のスクリプトが競合して書こうとしても、エラー側へ誤って案内しない。制御元の情報と計算結果はローカルな表示用データで、ワールド保存や参加者間の値同期には追加しない。

## 階層を編集する

左側は共有Slot階層。`World`で全体を表示し、`Focus`で選択中のSlotを表示の起点にする。`↑`は表示の起点を親へ移す。対象の選択と表示の起点は別々で、折り畳み状態もパネルごとに共有する。

`+ Child`で子の箱、`+ Text child`でWorldText付きの子Slotを作る。階層の項目を別の項目へドラッグすると、共有のワールド座標を保って親を変更する。`Move to world`で親を外す。親を削除すると子孫も削除する。自分自身や子孫の下への移動は拒否する。親の移動・回転・拡縮と、親のローカルDriveによる動きはRustが合成し、描画と衝突判定に渡す。

親のDriveはクライアントで評価するため、親変更で維持する共有のTransformと、その時点のローカルな見かけの位置は異なる場合がある。非一様スケールによるシアーは表現せず、位置・回転・スケールの合成として扱う。
子Slotのギズモは画面上ではワールド座標で動く。確定時には表示中の親の位置・回転・スケールから子のローカル`position`を求めて保存する。ドラッグ中の位置プレビューだけはワールド座標で共有する。

## 参照を渡す

Component名やフィールド名をドラッグすると参照を取り出せる。フィールド名を`Shift`を押してドラッグすると共有値のコピーになる。同じ型の編集欄の見出しに値を渡すと、通常の編集検証を通して反映する。

ウィンドウをまたぐ受け渡しでは、フィールド名を`Ctrl+右クリック`して参照を持ち、受け取り欄を左クリックする。もう一度`Ctrl+右クリック`すると手放す。共有値をコピーする場合は`Ctrl+Shift+右クリック`を使う。通常の右クリックは見出しの上でも3Dパネルの保持に使う。参照はSlot・Component・Fieldを区別し、親欄はSlot参照だけ、Luaの`field_ref`欄はField参照だけを受け取る。

Luaの公開パラメータに参照を定義できる。

```lua
return {
    name = "CopyPosition",
    fields = { source = {type = "field_ref", label = "Source position"} },
    drive = function(ctx)
        local value = ctx:read(ctx.self.CopyPosition.source)
        if value then ctx:drive(ctx.self, "position", value) end
    end
}
```

別の物体のPositionをこのパラメータへ渡すと、共有のローカルPositionを読んで自分のPositionをDriveする。`ctx:read`が読むのは共有の確定値で、他のDriveの評価結果ではない。参照先が未指定または削除済みなら`nil`を返す。現在の書き込み先は引き続きスクリプト自身の物体に限定する。

ワールドの正本、親子関係、参照の検証、共有値とDriveの評価はRust側にある。Godotが持つのは受信した表示用コピー、ウィンドウ配置、入力中の一時状態、参照を持っている操作状態、GPUリソース。ライト等を追加する場合も、保存する設定をRustに置き、影の計算など描画処理はレンダラへ任せる。
