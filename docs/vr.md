# デスクトップとVRの切り替え

状態：初期実装。WindowsとValve Indexを対象にする。実機での映像・操作・SteamVR再起動後の接続は未確認。
更新日：2026-10-28。

デスクトップで参加したセッションを維持したまま、VR表示へ切り替えられる。
ワールドとアバターの移動は同じRust Engineで動かし、VR用のGodotだけを別プロセスで起動する。
デスクトップの画面は裏で待機するため、VRを終えると元の画面へ戻る。
動画などの音声は操作中の表示側だけから出し、待機側ではミュートする。

## VRに入る

1. 開発版は`Debug.bat`でビルドして起動し、セッションに参加する。
2. SteamVRを起動し、Valve Indexを使える状態にする。SteamVRを有効なOpenXRランタイムに設定しておく。
3. PC画面右上の「VRに入る」を押す。

「VRを準備中…」の間はキャンセルできる。HMDの追跡と表示の準備が整うと、VR側へ操作を引き継ぐ。
失敗した場合はデスクトップを残し、理由と「再試行」を表示する。
編集中の値を送信している場合や撮影カメラを使用中の場合は、その操作を終えてから切り替える。

## Indexの操作

| 入力 | 動作 |
|---|---|
| 頭の動き | 見回し。手元の追跡を直接描画へ反映する |
| 左スティック | 視線の水平方向を基準に前後左右へ移動 |
| 右スティック左右 | 30度ずつ向きを変える。中立へ戻すと次の回転が可能 |
| 左B | 自分だけのVRメニューを開閉 |
| メニューを右手のレーザーで指し、トリガー | 「正面を合わせる」または「デスクトップに戻る」を選択 |

メニュー中、装着解除、追跡喪失、SteamVR側の入力フォーカス喪失では移動を止める。
復帰時はスティックを中立へ戻してから移動する。
PC窓が背面に回ったことだけではVR入力を止めない。

最初の対象は座位・立位のスティック移動。開始位置から頭が水平に0.6m以上離れた場合や、Rustが頭の位置を壁の中・近くと判定した場合は、視界を覆って移動を止める。
元の位置へ戻るか、左Bのメニューで正面を合わせる。部屋を歩き回るルームスケール移動はまだ対象外。

## デスクトップへ戻る

VRメニューの「デスクトップに戻る」、またはPC側に残る同名のボタンを押す。
アバターの現在位置を引き継ぎ、マウスを解放した状態へ戻る。ワールドをクリックするとFPS操作を再開できる。
SteamVRのセッション終了やVR表示プロセスの異常終了でも、デスクトップへ戻す。
SteamVRを起動し直した後は、再び「VRに入る」を押す。

VRでの把持・編集、共有する頭と手の詳細姿勢、撮影、立体視に合う鏡は後続の対象とする。
VR中は鏡面の表示をカメラ側で除外する。共有する鏡のデータは変更しない。

## 検証と実装の入口

`tests/vr-switch-integration.mjs --rendered`は、実際のPC側ボタン、別プロセスの起動、疑似追跡からRustへの移動入力、入力停止、スナップ回転、メニューの座標変換とトリガー、失敗・キャンセル・再入場・強制終了後の復帰を確認する。
疑似追跡による検証は、Indexの立体映像やSteamVRとの実接続の成功を保証しない。

2026-10-28の検証結果：

| 確認 | 結果 |
|---|---|
| VRの描画付き統合 | 疑似HMDで10回の往復、PCとVRメニュー双方からの復帰、失敗・キャンセル・期限切れ・強制終了を確認 |
| RustのCoreとEngine | 単一テストスレッドで109テストが成功 |
| 保存復元の統合 | ホスト保存、ゲストの保存先保持、クラッシュ後の復元、終了時保存と失敗時の再試行が成功 |
| HUDとUIフォーカスの描画付き統合 | 成功 |
| 既存のパネル統合 | 名前欄のクリックで失敗。変更前のクライアントを別フォルダーへコピーして同じ失敗を再現 |
| 既存の新規作成統合 | Mirrorの条件確認で失敗。変更前のクライアントでもMirrorの操作で失敗し、この確認は未完了 |
| Workspace全体のRustテスト | Scriptingの2テストがCPU実行時間の上限で失敗。今回その処理は変更していない |
| 警告をエラーにするClippy | 既存の引数数・型の複雑さ・同一分岐などの指摘で失敗 |

Windowsが予約しているポートとの衝突を避けるため、保存復元と一部の比較検証ではテストの一時コピーでポート番号を変更した。
Indexの実機確認と上記の既存テストの失敗解消は、配布前に残る確認項目とする。
